fix(dependencies): tolerate a UTF-8 BOM in JSON manifests

Found by RUNNING the new CLI rather than only unit-testing it. A package.json
written by PowerShell's Set-Content -Encoding utf8 failed to parse with 'Unexpected
UTF-8 BOM', and the whole npm ecosystem dropped silently out of the inventory.

A BOM is not whitespace to json.loads, but npm and Node both accept one, so refusing
it is stricter than the tools the manifest is written for. The failure is also invisible:
the file is simply absent from the inventory, which looks exactly like a project with
no JavaScript dependencies.

Verified the new tests fail without the fix (2 of 3 fail) and pass with it.
Suite: 406 -> 408 passing.
